# 伴读 Margin

**在线使用：<https://aihelpread-2db.pages.dev/>**（打开即用，第一次在「设置 → 模型」里填自己的 API Key）

数据全部留在本地浏览器（IndexedDB），无账号、无后端、无埋点；模型与检索都用你自己的 Key。

## 功能

| 能力 | 说明 |
| --- | --- |
| 导入文档 | PDF、EPUB、Word(.docx)、Markdown、纯文本；浏览器本地解析，不上传 |
| 书架与进度 | 记录每篇读到哪一段，下次接着读 |
| 分类文件夹 | 自定义文件夹把文档分类存放；删除文件夹只解散分类，不删文档 |
| 脉络大纲 | 自动提取文档结构，侧栏点击跳转 |
| 划词解释 | 三层回答：它在论证里做什么 / 最小定义与前置概念 / 要不要深究；必须引用原文；可存成「解释」类批注 |
| 概念速释 | 针对选中的术语或理论名，给出 ① 学术上公认的一句话定义 ② 概念细节（前提 / 构成 / 机制 / 本质 / 出处）③ 在本文这一处指什么；可存成「概念」类批注 |
| 页边批注 | 左侧是目录与记录，右侧一条跟正文共用滚动条的批注栏：卡片落在对应划线的真实高度上，随页面一起上下走（PDF / EPUB / Word / Markdown 都支持）；左右两栏都能单独开关；内容、类别都能就地改 |
| 划词提问 | 选中一段话写下问题，AI 结合全文上下文、模型知识与联网检索结果回答；问答卡片同时出现在左右两栏，可在卡片里接着多轮追问，不占划线分类 |
| Word 公式 | .docx 里的公式（OMML）转成 MathML 显示，不再是一段空白 |
| 颜色自定义 | 设置 → 外观：批注 / 划线 / 查证两类标记的颜色都能单独改，也能改名、增删批注类别 |
| AI 点评 | 对一条批注追问依据、要反例、指出跳步；追问式 / 纠错式两种姿态 |
| 联网查证 | 先检索、再读前几条结果正文，只依据资料判断「支持 / 部分支持 / 与资料矛盾 / 资料不足」，逐条标出处；未联网会明确说明。用 DeepSeek 时直接交给模型原生联网搜索，回答自带角标引用 |
| 查证记录 | 每条查证留在侧栏，展开回看当时的结论与出处，可回到原文或删除 |
| 思考档位 | 设置 → 模型：每个功能单独选「直接答 / 想一下 / 认真想」。解释、概念、提问默认不思考（快），点评、查证、骨架默认认真想（稳） |
| 依赖地图 | 抽取论点、前提、定义与「读懂 B 先懂 A」的依赖边，生成按依赖排序的阅读路线 |
| 防剧透 | 默认给模型全文上下文；在设置里打开「不剧透」后，只把阅读前沿之前的内容发出去 |
| API 用量 | 设置 → 用量：本机记录每次调用的输入/输出 token、缓存命中、思考 token、联网次数，按今天 / 近 7 天 / 总计与功能、模型分列，并折算成大致花费，可清空 |
| 主题与字号 | 纸感 / 素白 / 夜读，字号 15–24 |
| 备份 | 导出 JSON、导出 Markdown 读书笔记、导入恢复 |

## 本地运行

需要 Node 20+ 与 pnpm。以下命令都在项目根目录执行：

```bash
pnpm install

pnpm dev        # 开发模式，http://localhost:5188
pnpm build      # 生产构建，产物在 dist/
pnpm typecheck  # TypeScript 类型检查
pnpm serve    # 托管 dist/ 并提供 /api/proxy 转发，默认 http://127.0.0.1:8787
```

只想自己用：`pnpm build && pnpm serve`，浏览器打开 `http://127.0.0.1:8787` 即可。

## 配置模型

打开「设置 → 模型」：

1. 内置只预置 DeepSeek：BaseURL 为 `https://api.deepseek.com`，模型是 `deepseek-flash`（便宜）与 `deepseek-v4-pro`（更强），填 API Key 即可；
2. 想接别家（通义、Kimi、GLM、OpenAI、本地 Ollama……）用「添加自定义」，填那个服务的 OpenAI 兼容 BaseURL 与模型名；
3. 勾上「经本地转发」，请求走 `/api/proxy`，避免浏览器 CORS 报错；
4. 点「测试连接」确认可用；
5. 同一页下面的「要不要先想再答」可以给每个功能单独设档位：解释 / 概念 / 提问关掉最快，点评 / 查证 / 骨架保留「认真想」。开启思考后服务端会忽略 temperature，并额外按思考 token 计费。

本地模型（Ollama 等）把 BaseURL 指向 `http://127.0.0.1:11434/v1`，不需要 Key。

## 配置联网查证（可选）

默认就是「DeepSeek 搜索」：直接复用你在「设置 → 模型」里填的 DeepSeek Key，不用再买第二个检索服务，也没有别的检索服务需要配置。一次查证的顺序是：搜 3–5 条 → 打开前 3 条正文 → 只依据这些资料给结论。检索接口返回长摘要和正文 Markdown，比自建扒网页更干净。

## 数据与隐私

- 文档正文、批注、划线、查证、设置全部存在浏览器 IndexedDB（库名 `margin-reader`）。
- 只有主动划词、写批注、生成地图时，才会把当前段落（默认还带上全文上下文）发给模型；设置里打开「不剧透」可以改回只看已读。
- 「查证」会把选中的句子发给检索服务；用 DeepSeek 时检索与读页都在 DeepSeek 侧完成，不再把网页内容转给第三方。抓取内容只用于本次核查，不落库。
- 用量只记 token 数量与本机估算，不上传。无遥测。清除站点数据会丢失记录，建议定期用「导出 JSON」备份。

## 目录结构

```
margin/
├─ src/
│  ├─ components/   阅读器、书架、页边批注、划词条、动作浮窗、设置
│  ├─ ingest/       PDF / DOCX / MD / TXT → 统一块模型（含大纲）
│  ├─ ai/           厂商预设、OpenAI 兼容流式客户端、检索、提示词、任务封装
│  ├─ lib/          锚点与高亮、Markdown 渲染、备份导出

├─ server/          本地静态托管与 /api/proxy（零依赖）

├─ scripts/         构建产物自检
└─ dist/            构建产物
```

## 技术栈

TypeScript（strict）· React 19 · Vite（rolldown）· zustand · Dexie（IndexedDB）· pdf.js · mammoth · markdown-it + DOMPurify · CSS Custom Highlight API。

## 已知限制

- PDF 扫描件没有文本层，暂不支持（需要 OCR）。
- EPUB 只提取文字与标题，书里的图片、图表、脚注弹窗不显示；带 DRM 的电子书打不开。
- PDF 按文本行重建段落，复杂分栏或表格可能串行；Word 复杂版式会被简化。Word 公式覆盖分式、上下标、根号、求和、矩阵等常见结构，少数专有写法会降级成文字。
- 依赖地图由模型一次生成，长文档可能只覆盖主干。
- 移动端为基础响应式，最佳体验在 ≥ 1040px 宽度。
